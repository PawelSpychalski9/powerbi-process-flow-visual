# M00–M03 validation

For the Format pane, theme, high-contrast, and permission checks introduced in
M03, see [formatting and usability](formatting.md).

## Repeatable local checks

Run from `process-flow/`:

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run package
npm.cmd run preview
npm.cmd run test:browser
```

The tests cover the sample CSV (eight nodes, nine edges), role-based column
lookup, schema validation against the installed SDK, missing and invalid data,
signed values, parallel edges, conflicting source metadata, repeated keys,
cycles, self-loops, disconnected components, layout determinism, sample bounding
box collisions, safe text rendering, resize, data replacement, error recovery,
instance marker isolation, and a 500-node chain.

The preview command writes `.tmp/sample-preview.html`. Open that file in a browser
for a standalone fixture preview generated by the same parser, layout, renderer,
and stylesheet as the visual. This is not a Power BI host or an end-to-end report
test. Keep preview artifacts outside version control.

## Manual Power BI checklist

1. Import `example_data/example_data.csv` using Get data → Text/CSV. Set Source,
   Target, Tooltip ID, Node Title, Node Description, Label, and Group to Text;
   set Value to Decimal number. Load the table.
2. Run `npm.cmd run package` from `process-flow/`. Import the generated `.pbiviz`
   from `process-flow/dist/` through the report's custom visual import menu.
   Tenant policy may restrict custom visual imports. This package is not certified.
3. Add the visual to the report. Before assigning data, the host may show its own
   empty-field placeholder. Assign Source, Target, and Value to the matching wells.
4. Assign all optional fields to matching wells, especially the unique Tooltip ID
   so the host keeps individual connections. Use the sample's raw Value column
   with Sum at this unique edge grain. Compare against a built-in table with the
   same fields if using a different measure or aggregation.
5. Verify the summary reads **8 nodes · 9 edges**. Check A → B; B → C and B → D;
   C → E and D → E; E → F and E → G; F → H and G → H.
6. Verify B → C displays **-18**, B → D displays **-5**, and C → E displays **-10**.
   Negative values must not reverse arrow direction. H should show its ID; A
   should show Ingestion. The optional edge Label must not replace numeric Value.
7. Check the bottom-left **−**, **+**, percentage, and **Fit** controls. The initial
   scale is 100%. Click Fit: the whole graph should fit in both dimensions, with
   scroll positions reset. Resize it while Fit is active: the graph should fit
   again. Click +: the scale should increase and scrollbars should appear when
   needed. Scroll and verify that the controls remain at the bottom left. A manual
   scale should survive resize and host refresh. Verify there is one graph, eight
   nodes, and nine edges throughout.
8. Filter the built-in table and graph together; clear the filter. Verify graph
   contents update without stale or duplicate nodes. Filter out all rows and check
   the empty state. Remove a required field and check the host/visual instructions.
9. Remove the optional fields: connections should still render using node IDs and
   numeric labels. Reassign them and confirm titles and labels return.
10. In a disposable test table, try a self-loop, a cycle, parallel edges with
    distinct Tooltip IDs, disconnected nodes, zero values, nulls, and long labels.
    Check for readable warnings and no crashes. Do not modify the baseline CSV.
11. Capture a screenshot with the visual enlarged and all eight nodes visible,
    plus the field wells if possible. Include a second screenshot at a smaller
    size and report any JavaScript errors or differences from the local preview.

Actual field assignment, host aggregation, and visual appearance in Power BI
Desktop/Service still require a report-author check. Local DOM tests and package
success do not establish Power BI end-to-end behavior.

## Initial layout and known limitations

- No layout dependency was added. Iterative strongly connected components are
  condensed to a DAG, ranked by longest path, and placed in stable ID order.
  Cyclic components share a column with separate outside routes; self-loops and
  longer connections have explicit routes. Disconnected nodes remain visible.
- Nodes have two bounded title lines and an optional ID line. Node dimensions grow
  with configured font size. Long text is shortened. Numeric labels retain the
  sign, use automatic or author-selected decimal precision, and switch to
  scientific notation for extreme magnitudes.
- Spacing keeps the sample's node and label boxes separate. This is an initial
  layout, not an optimal crossing minimizer or obstacle-avoiding router. Dense
  graphs, many parallel edges, and complicated cycles can still produce crossings
  and label overlap. No general overlap-free guarantee is made.
- The sample uses a natural canvas of approximately 1,900 pixels in width. At 100%
  smaller report visuals scroll. The zoom controls change scale by a factor of
  1.25, up to 400%. Fit can scale below 10% for large graphs, so tiny report areas
  may make labels too small to read; zoom in and scroll to inspect them. Fit mode
  follows viewport changes, while manual scale and scroll position are retained
  across host updates. These navigation settings are per visual instance for the
  current session, not persisted in the report. Drag-to-pan and wheel zoom are not
  implemented; use scrollbars and the buttons.
- M03 adds five formatting cards, host theme and high-contrast colors, implemented
  landing/error states, and a static auto-fit mode when interactions are disabled.
  See [the M03 guide](formatting.md) for settings and manual validation.
- This milestone has no Power BI selection identities, cross-filtering, report
  tooltips, context menus, or complete keyboard navigation. Packaging warnings
  remain visible for these later features.
- See [the data contract](data-contract.md) for row grain, duplicate policy, host
  grouping caveats, incomplete-result rejection, and the 1,000-edge/500-node limits.
- Added test dependencies `jsdom` and `ajv` are MIT-licensed. Test preview uses the
  LESS compiler already supplied by Power BI Visuals Tools. No remote runtime
  services or scripts are used by the visual.
